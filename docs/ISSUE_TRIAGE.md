# 公开反馈与分诊

> 本文件面向公开仓库（`brick_bookmark_profile`）的使用者与维护者。内部跨仓库协同协议不放在公开仓库，避免暴露私有仓库与内部计划。

## 提交前

- 先搜索已有 issue，避免重复；
- 不要填写账号、密码、书签内容、浏览记录等隐私信息；
- 附上扩展版本、浏览器版本、操作系统和复现步骤。

## 分诊流程

1. 新 issue 自动带 `needs-triage`（或由维护者补上）；
2. 维护者确认类型：`bug` / `enhancement` / `question`；
3. 需要发版修复的，维护者在内部跟踪，并在公开 issue 回复进展；
4. 修复发布后，在公开 issue 回复版本号，再关闭；**不删除 issue**。

## 边界

- 公开 issue 只讨论产品使用与可复现问题，不讨论内部实现细节；
- 内部 issue 与公开 issue 互相引用时，只引用公开链接；
- 涉及安全漏洞的，请先私下联系维护者，不要直接开公开 issue。
